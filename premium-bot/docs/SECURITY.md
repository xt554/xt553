# 生产安全清单

## 必做

- 运行 `scripts/deploy.sh` 生成随机数据库密码、JWT Secret 和内部 Token。
- 首次登录后更换管理员密码；生产环境不要保留开发 `.env`。
- 正式环境默认禁止 Mock 发放渠道；测试生产拓扑时必须显式开启例外。
- `.env` 权限设为 `600`，仅部署账户可读。
- MySQL、Redis 不映射公网端口；只通过 Compose 内网访问。
- 启用 HTTPS，并在上层防火墙只开放 22、80、443。
- Telegram Token、RPC Key、Provider Token 定期轮换。
- 收款服务只保存公开地址；助记词和私钥放在独立签名设备/托管系统。
- 对退款启用人工审批、单笔/单日限额和目标地址校验。
- 定期备份 MySQL，并演练恢复。
- 对 `FAILED`、`UNMATCHED`、Worker 重试耗尽、余额异常建立告警。
- 把用户余额视为平台负债，限制人工调账权限并每日进行四方对账：
  链上交易、充值单、钱包账本、用户余额。

## 接口

- 管理端使用短期 JWT，刷新 Token 默认 7 天。
- Bot 内部 API 使用独立 Token，不暴露给浏览器。
- 支付与 Provider Webhook 使用原始 Body HMAC-SHA256。
- Nginx 为 API 设置基础速率限制；生产可在 CDN/WAF 增加更严格规则。
- `callback_url` 仅供可信调用方使用；公开开放下单 API 时应增加 SSRF 目标白名单。

## 已知边界

- 内置扫描器是轻量级实现，不代替高可用区块链索引器。
- EVM 回扫 20 区块只能覆盖常见短重组；高价值业务应使用更深确认及多节点交叉验证。
- TronGrid 分页上限适合中低交易量；高交易量钱包应实现 fingerprint 分页或专用索引器。
- 唯一金额尾数依赖用户精确转账；错额进入人工队列。
- 管理员人工加款/扣款会写钱包流水和审计日志，但生产环境仍建议增加
  双人审批、单日限额和异常余额告警。
- 管理后台目前把 JWT 放在 `localStorage`；更高安全等级可改成同站 HttpOnly Cookie + CSRF 防护。
