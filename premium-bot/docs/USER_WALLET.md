# 用户 USDT 钱包

## 功能范围

- 每位 Telegram 用户自动创建一个 USDT 钱包账户。
- 用户可选择 TRC20、BEP20 或 ERC20 创建充值单。
- 达到收款钱包确认数后自动入账。
- 创建 Premium 订单时可选择链上支付或钱包余额支付。
- 余额支付订单最终失败时自动退款到钱包。
- 管理后台支持钱包查询、充值单查询、余额流水和有审计记录的人工调账。

钱包是平台内部记账余额，不生成私钥，也不为每位用户创建链上地址。
充值复用后台配置的公开收款地址，并用精确金额尾数区分并发充值单。

## Bot 操作

```text
/wallet
```

选择“充值”，输入金额并选择网络。必须按机器人显示的精确金额和地址
转账。到账后，重新打开 `/wallet` 即可查看余额。

购买套餐时，在输入目标 Telegram 用户名后选择：

- `钱包余额支付`：立即扣减套餐标价并进入发放队列；
- `USDT 链上支付`：按原流程创建待支付订单。

## 账本规则

| 类型 | 余额方向 | 说明 |
| --- | ---: | --- |
| `DEPOSIT` | 增加 | 链上充值确认 |
| `ORDER_PAYMENT` | 减少 | Premium 订单余额支付 |
| `ORDER_REFUND` | 增加 | 发放失败自动退款 |
| `ADMIN_CREDIT` | 增加 | 管理员人工加款 |
| `ADMIN_DEBIT` | 减少 | 管理员人工扣款 |

每条流水保存变动金额、变动后余额、业务引用和唯一幂等键。不要直接修改
`user_wallets.available_balance`；任何修正都应通过调账接口写入流水。

## 状态与幂等

充值单状态为 `WAIT_PAY → CONFIRMED`，超时则为 `TIMEOUT`。超时后 24
小时内到账仍可自动确认。链上交易唯一键和充值账本幂等键共同保证重复
扫描不会二次入账。

余额订单的扣款尝试带序号。管理员重试已退款订单时会产生新的扣款流水；
若重试仍失败，对应尝试会产生且只产生一条退款流水。

## 配置

```dotenv
DEPOSIT_EXPIRE_MINUTES=60
WALLET_MIN_DEPOSIT=1
WALLET_MAX_DEPOSIT=10000
```

充值网络复用 `ENABLED_NETWORKS`、链上 RPC、Token 合约、确认数与后台
收款钱包配置。
